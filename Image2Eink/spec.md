# Egg Studio: Spec for a 1-bit E-Ink Image Cropper and Converter

> **Historical note.** This spec was written for the Heltec Vision Master E213 at a fixed 250 x 122. The app now lets you pick the output size (CrowPanel 4.2" 400 x 300 by default, the Heltec, or custom); see `README.md`. The header format below is unchanged apart from the size.

## 1. Purpose

Build a small local web app for preparing images for a 250 x 122 pixel, 1-bit (black/white) e-ink display. The user loads a batch of photos or pixel art, goes through them one at a time, picks the exact region to use with zoom and pan, tunes the black/white conversion while watching a live preview, and exports a single C header file (`easter_eggs.h`) that drops straight into an existing Arduino sketch.

This replaces an existing command-line converter (`convert.js`, Node + sharp). Its output format must be matched exactly so the firmware does not change.

## 2. Context

- **Hardware:** Heltec Vision Master E213, ESP32-S3, 2.13" e-ink panel.
- **Panel geometry in the firmware's orientation:** 250 px wide, 122 px tall, landscape.
- **Firmware:** Arduino sketch `cabin_hud.ino`. When the user presses a button, it picks a random image from `easter_eggs.h` and draws it full-screen with Adafruit GFX:
  ```cpp
  display.drawBitmap(0, 0, EGGS[i], EGG_WIDTH, EGG_HEIGHT, BLACK);
  ```
- The sketch includes the header with `#include "easter_eggs.h"` and uses only these symbols: `EGG_WIDTH`, `EGG_HEIGHT`, `EGGS[]`, `EGG_NAMES[]`, `EGG_COUNT`.
- **Expected volume:** a few dozen images. Each is 3,904 bytes, so 40 images is about 153 KB of flash, which is fine.

## 3. Output format (hard requirement)

The export must produce a header in exactly this shape:

```c
// Auto-generated by Egg Studio. Do not edit by hand.
// N image(s), 250x122, 1-bit, 3904 bytes each, TOTAL bytes total.
// Format: Adafruit GFX drawBitmap (MSB first, rows padded to bytes, 1 = black).
#pragma once
#include <Arduino.h>

#define EGG_WIDTH  250
#define EGG_HEIGHT 122

// source-file-name.jpg  (dither, floyd-steinberg)
static const uint8_t egg_source_file_name[] PROGMEM = {
  0x00, 0x1f, 0xff, ...  (16 bytes per line)
};

// ... one array per image ...

static const uint8_t* const EGGS[] = {
  egg_source_file_name,
  ...
};

static const char* const EGG_NAMES[] = {
  "source-file-name",
  ...
};

static const uint16_t EGG_COUNT = N;
```

**Bit packing (must be exact):**
- Row-major, top row first.
- Each row is `ceil(250 / 8) = 32` bytes. The last 6 bits of each row are padding and must be 0.
- Within a byte, the most significant bit is the leftmost pixel: pixel `x` sits in byte `x >> 3`, mask `0x80 >> (x & 7)`.
- **Bit 1 means a black pixel.** Bit 0 means white, which is the background, because the firmware clears to white before drawing.
- Total bytes per image: `32 * 122 = 3904`.

**Identifiers:**
- Each array is named `egg_` plus the image name, lowercased, with runs of characters outside `[a-z0-9]` replaced by `_` and leading or trailing `_` trimmed.
- Duplicate names get `_2`, `_3` and so on. An empty result becomes `egg_img`.
- In `EGG_NAMES`, escape `\` and `"`.

## 4. Users and workflow

There is one user: technically fluent, on Windows, running this locally. The workflow:

1. Open the app (it runs locally in a browser) and drag a folder or a batch of image files onto it.
2. The images appear as a thumbnail strip or sidebar list.
3. Select an image. It opens in the editor with a crop frame locked to the panel's aspect ratio.
4. Zoom and pan to frame the shot, then adjust the conversion settings while watching the live 1-bit preview.
5. Mark the image as done (or excluded), then move to the next with a keyboard shortcut.
6. Export `easter_eggs.h` at any point. The export includes all images that aren't excluded, in list order.
7. Close the app and come back later with all crops and settings intact.

## 5. Functional requirements

### 5.1 Import
- Accept drag and drop of multiple files and folders, plus a file picker.
- Formats: JPEG, PNG, GIF (first frame), WebP, AVIF, BMP, and anything else the browser can decode.
- Respect EXIF orientation. `createImageBitmap(file, { imageOrientation: 'from-image' })` does this, as does the browser default in current Chromium and Firefox.
- Composite transparency onto white.
- Default name is the file name without its extension. Allow renaming.

### 5.2 Image list
- A sidebar with a thumbnail, the name, and a status (new / edited / done / excluded) for each image.
- Reorder by drag and drop. The order sets the array order in the header.
- Remove an image, or toggle exclude.
- Show a running count and the total flash size (`included * 3904` bytes, in KB).

### 5.3 Crop editor
- Show the source image in a large viewport with a crop rectangle **locked to 250:122** (about 2.049:1).
- **Zoom:** mouse wheel or trackpad pinch, centred on the cursor. Range about 0.05x to 32x of source pixels. Show the zoom level.
- **Pan:** drag the image, either with the crop frame fixed in the middle of the viewport or by dragging the frame itself. Either model is fine as long as it's consistent. Recommended: fixed frame, move the image underneath.
- **Resize** the crop by dragging its corners, keeping the aspect ratio locked.
- **Buttons:**
  - **Fit:** the whole image fits inside the frame, with white margins allowed.
  - **Fill:** the frame is covered, cropping edges.
  - **Centre.**
  - **Reset.**
  - **Rotate 90° left and right.**
  - **Flip horizontally.**
- Allow the crop to extend past the image edges. Areas outside the source render as white.
- **Keyboard:**
  - Arrow keys nudge by 1 output pixel, Shift + arrow by 10.
  - `+` and `-` zoom.
  - `F` fit, `G` fill.
  - `N` / `P` or `J` / `K` next and previous image.
  - `D` toggle done, `X` toggle exclude.
- Store the crop in **source pixel coordinates** (x, y, width, height, rotation, flip), so it doesn't depend on viewport or zoom.

### 5.4 Conversion settings (per image, with a "copy settings to all" button)

| Setting | Values | Default |
|---|---|---|
| Mode | Auto, Dither, Threshold, Pixel art | Auto |
| Dither algorithm | Floyd-Steinberg (serpentine), Atkinson, Ordered Bayer 4x4, Ordered Bayer 8x8 | Floyd-Steinberg |
| Threshold | 0 to 255 | 128 |
| Brightness | -100 to +100 | 0 |
| Contrast | -100 to +100 | 0 |
| Gamma | 0.3 to 3.0 | 1.0 |
| Auto-levels (contrast stretch) | on/off | on for Dither, off otherwise |
| Sharpen (applied before quantising) | 0 to 100 | 0 |
| Invert | on/off | off |

- **Auto mode:** count distinct colours on a downsampled copy, capped at 33. With 32 colours or fewer, use Pixel art. Otherwise use Dither. This matches `convert.js`.
- **Pixel art mode:**
  - Resample with nearest-neighbour.
  - Offer a **"snap to integer scale"** option that rounds the crop size so each source pixel maps to an exact N x N block of output pixels.
  - Show the current scale factor (for example "6x").
  - Use a hard threshold, with no dithering.
- **Greyscale conversion:** use Rec. 709 luma on sRGB values: `0.2126 R + 0.7152 G + 0.0722 B`. Converting to linear light first is a nice-to-have. If you do it, make it a toggle.
- **Processing order:** crop/rotate/flip → resample to 250x122 → greyscale → auto-levels → brightness/contrast/gamma → sharpen → dither or threshold → invert → pack.

### 5.5 Resampling quality
- Photos are usually being downscaled a lot (for example from 4000 px to 250 px). Use a high-quality method:
  - Repeated halving with canvas `imageSmoothingQuality = 'high'` until within 2x of the target, then a final step.
  - Or a Lanczos / area-average implementation in JS or WASM.
- Plain single-step canvas `drawImage` downscaling aliases badly and should not be used.
- Pixel art mode always uses nearest-neighbour (`imageSmoothingEnabled = false`).

### 5.6 Live preview
- Show the result at actual output resolution next to the editor, scaled up 2x to 4x with crisp pixels. Let the user switch the scale.
- Add an **"e-ink look" toggle**:
  - Draw white as a slightly warm off-white, about `#e8e6df`.
  - Draw black as a dark grey, about `#2b2b2b`.
  - Optionally add a subtle paper texture.
- Show the preview at **true physical size** as an option. The panel's active area is about 48.6 mm x 23.7 mm, roughly 130 DPI. The user enters their monitor's DPI, or calibrates against a credit card.
- Update within about 100 ms of any change while dragging. Run processing in a Web Worker so dragging stays smooth (OffscreenCanvas or raw buffers).
- Show a before/after toggle or a split slider between the greyscale crop and the 1-bit result.

### 5.7 Export
- **Export `easter_eggs.h`:** downloads the file, or writes it straight to a folder the user picks with the File System Access API, so it can overwrite `cabin_hud/easter_eggs.h` directly. Remember that folder handle.
- **Export previews (ZIP):** a PNG of each 1-bit result at 1x and 3x.
- **Export single image:** the C array for one image, to paste into a header by hand.
- Before writing, check that every array is exactly 3,904 bytes and that the identifiers are unique.

### 5.8 Persistence
- Auto-save the whole project to IndexedDB: source image blobs, names, order, crop, settings and status. Reopening the app restores everything.
- **Save project / Open project:** a single `.eggproj` file (a ZIP with `project.json` and the original images), for backup or moving between machines.
- The project JSON schema is versioned (`"version": 1`).

## 6. Non-functional requirements

- **Client-side only.** There's no backend and nothing is uploaded anywhere. It must work offline after first load.
- **Stack** (Claude Code may substitute equivalents):
  - Vite + TypeScript.
  - Plain DOM or a light framework (Preact, Svelte or Solid). Avoid heavy UI kits.
  - Canvas 2D for rendering. No server-side image libraries.
- **Run:** `npm install` then `npm run dev`. `npm run build` produces a static `dist/` that works when opened from a local static server.
- **Browsers:** current Chrome or Edge on Windows. Where File System Access isn't available (Firefox), export falls back to a normal download.
- **Performance:** handles 50 images of 12 MP or more without the tab running out of memory. Keep thumbnails and a downscaled working copy (long edge about 2,000 px) in memory. Only crop from the full-resolution source when the crop is zoomed in far enough to need it.

## 7. Code structure (suggested)

```
src/
  main.ts            app bootstrap, layout, keyboard shortcuts
  state.ts           project model, undo/redo, IndexedDB persistence
  import.ts          file and folder ingest, EXIF orientation, thumbnails
  editor/
    viewport.ts      zoom/pan/crop interaction, source-coordinate math
  pipeline/
    worker.ts        runs the processing chain off the main thread
    resample.ts      high-quality downscale, nearest for pixel art
    adjust.ts        greyscale, levels, brightness/contrast/gamma, sharpen
    dither.ts        floyd-steinberg, atkinson, bayer, threshold
    pack.ts          1-bit packing (Section 3 rules)
  export/
    header.ts        easter_eggs.h generation, identifier sanitising
    zip.ts           previews and .eggproj (use a small lib such as fflate)
  ui/                sidebar, settings panel, preview panel
tests/
```

Undo/redo per image (crop and settings) is required. Ctrl+Z and Ctrl+Shift+Z.

## 8. Acceptance tests

Automate as unit tests (Vitest or similar):

1. **Packing:**
   - An all-white image packs to 3,904 bytes of `0x00`.
   - With a single black pixel at (0, 0), byte 0 is `0x80` and every other byte is 0.
   - With a black pixel at (249, 0), byte 31 is `0x40`. Pixel 249 is bit index 1 in byte 31.
   - With a black pixel at (0, 121), byte `121 * 32 = 3872` is `0x80`.
   - For an all-black image, every row is `0xFF` x 31 then `0xFC`. The padding bits stay 0.
2. **Identifiers:**
   - `"My Photo (1).JPG"` becomes `egg_my_photo_1`.
   - Two images named `cat` become `egg_cat` and `egg_cat_2`.
   - `"!!!"` becomes `egg_img`.
3. **Header compiles:** generate a header with 3 images, compile it with `g++ -Wall` on the host after defining `PROGMEM` as empty and removing the Arduino include. Check `sizeof` of each array is 3904 and `EGG_COUNT == 3`.
4. **Dither sanity:** a flat 50% grey input dithered with Floyd-Steinberg comes out 50% black, plus or minus 2%. Threshold mode on the same input at threshold 128 comes out all white (128 is not below 128).
5. **Crop maths:**
   - A crop at zoom 1 with no rotation, exported from a 500x244 source with crop rect (0, 0, 500, 244), equals a 2x downscale of the source.
   - Rotating 90° four times returns the original crop.
6. **Persistence:** reloading the page restores the image list, crops and settings unchanged.

**Manual check:** flash a header with a test pattern onto the device. Use a 1 px border, a diagonal, and the image name in the top-left corner. Confirm there's no offset, mirroring or inversion.

## 9. Out of scope

- Sending images to the device over Wi-Fi or USB. The user reflashes with the Arduino IDE.
- Greyscale or multi-level e-ink output. The panel is used in 1-bit mode only.
- Animation.
- A backend, user accounts or cloud sync.

## 10. Nice-to-haves (only after everything above works)

- A **text overlay tool:** add a caption in a pixel font, rendered after dithering so it stays crisp.
- **Batch auto-crop:** start each new image with a centre "Fill" crop so only adjustments are needed.
- **Edge-aware dithering:** a threshold boost on strong edges to keep outlines crisp in photos.
- **Side-by-side dither comparison:** a 2x2 grid of all four algorithms for the current crop, so the user can pick one at a glance.
